# 简洁与认知负担规范

版本：2.0.0-beta.1。2026-10-10。适用于 Rosemary 网站、组件文档和原生组件库。

## 先回答当前任务

默认界面先回答用途、当前状态、下一步。首页是进入指南的入口，不重复整本指南。栏目页用一至两句说明用途；组件详情首先提供实际演示、使用规则和必要的无障碍信息。

每组操作突出一个主要动作；次要动作保留明确名称。目录先显示一批结果，搜索覆盖完整清单；分类、数量和生效条件仍可见。

## 分层阅读

删除重复导语、口号和重复说明。同一段优先不超过三句，一段说明一件事；长文先给摘要，再分成有意义的章节。首页首屏只给一条用途说明和主要入口。

源码、完整参数、平台细节、历史记录采用按需展开。展开标签说明将读到什么，不能都写“更多”。不超过一层常规阅读披露；源码文件等技术参考可以有明确命名的第二层。

错误、风险、当前选中条件、未保存状态、支持范围和必要的恢复动作不能隐藏。禁止通过小字、裁切、消失的图标或去掉功能来制造简洁。专业用户可以直接进入完整规范和源码。

## 保持可达

章节使用真实标题和稳定 ID；已有 URL 保持兼容。直接访问折叠章节时自动展开目标和祖先，再定位。披露采用原生 details/summary，可由键盘打开，关闭时恢复到摘要控制。浏览器页面查找、辅助技术和网站检索的结果需要人工验证，不能仅以隐藏 DOM 存在作为可达证明。

页面重排保留正文尺寸、足够间距和原有控件热区。行宽、字体缩放和 320px 布局需实际检查；文档不会用压缩字号换取短页面。

字段标签与控件保留明确间距，常规字段上下排列、间隔 8px；紧凑的横向布局也须明确留空。折叠动画和滚动容器不能截断可操作控件的焦点轮廓；保留足够绘制空间，并在实际聚焦状态验收。

## 文案真实

按钮使用具体动词，反馈对应真实状态。只在确实持久化后声称“已保存”；权限申请说明当前用途。组件参考、设计草案和已发布库清楚区分，重要边界始终可见。

## 验收

1. 在固定视口记录默认可见正文的字符数和页面高度，仅作为编辑回归指标。
2. 检查用户能否找到入口、识别状态、读到必要风险、完成下一步；不用字数代替任务验证。
3. 检查折叠章节的点击、Tab/Enter、直接访问、历史返回和浏览器查找。
4. 复查明暗主题、窄屏、文本重排、图标与触控目标；全文不被删除。

一句导语、一段不超过三句、默认十二项目录是 Rosemary 编辑预算，不是 Apple / WCAG 规定的通用数字或合规门槛。

## 来源

- [Apple HIG — Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)：相关时才展示细节，常用内容保持可见。
- [Apple HIG — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：清晰层级与渐进披露。
- [W3C WAI — Clear and understandable content](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o3-clear-content/)：清晰词语、短句、短文本块与长文摘要；这是 WCAG 补充建议。
- [WAI — Writing for web accessibility](https://www.w3.org/WAI/tips/writing/)：有意义的标题、链接和简洁内容。

以上原则为依据；具体页面结构和编辑预算是 Rosemary 的决定，不据此声明无障碍认证。
