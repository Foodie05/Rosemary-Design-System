# SDK 0.4.1 consistency review · 2026-10-15

This patch reviews the SDK against the portal's component demos, custom-select styling, shared contracts and generated icons/tokens. Forma remains **1.2.0**. The reported missing dropdown cue belongs to Select and the gallery's component chooser; ordinary Checkbox controls do not receive dropdown arrows. The existing 33-component catalog is unchanged. This is a targeted review and automated smoke coverage, not a claim that all 33 components received complete manual acceptance.

## Findings and fixes

| Implementation | Confirmed problem and resulting change |
| --- | --- |
| Android Compose | Select reused a text-only secondary button. Its field trigger now has a persistent shared `down` icon, field ink/surface colors, accessible label/expanded state, danger border/soft background for errors, and canvas/muted with one .65 opacity when disabled. Disabled options are muted; disabling an open Select closes its popup. Options reserve space for a persistent shared `check` tied to the committed value, independently of keyboard focus. |
| Android Compose | Installed-app screenshots showed popups covering their own trigger. The shared native popup position provider now prefers below the anchor, flips above when possible, aligns to inline start in LTR/RTL and constrains position to window margins. The fallback for a very tall popup is explicitly tested. Date/time and Upload entries use the existing calendar/clock/upload icons; the gallery Actions entry has a disclosure cue. Input/Textarea now show disabled and invalid field states. |
| Flutter | Select lacked its disclosure cue, field styling and a committed selection marker independent of keyboard activity. Shared down/check icons, field states and value-based selection semantics now match the reference. Date/time entry and calendar view selectors, plus the gallery Actions entry, expose their existing icon cues. Mixed Checkbox referenced a nonexistent `minus` icon; it now draws a dash without throwing. |
| SwiftUI | Menu lacked its disclosure cue. Shared FieldFrame omitted disabled and invalid backgrounds; it now uses canvas/muted/.65 and dangerSoft. Skeleton previously remained static: it now uses the shared skeleton cycle, stops for reduced motion/inactive scenes and exposes an optional `isRunning` argument with a compatible default. Capture fixtures document the cues and static skeleton state. |
| React | Read-only, disabled and invalid fields omitted reference background/color/opacity rules. Long Select/Menu labels could shrink their disclosure icons. Field CSS now matches these states; wrapping labels preserve full icon dimensions. Browser regressions check light/dark, 375/1280px layouts, interactions and horizontal overflow. |

Select's shared `down` remains static in open and closed states across implementations. Existing public call sites remain compatible. The SDK/package, consumer, CI artifact and release-assembly versions move together to **0.4.1**; no public registry publication is introduced. Published 0.4.0 tags/assets and historical verification records remain unchanged.

## Evidence boundaries

All local runs use the working candidate; installable release acceptance still requires successful exact-main CI and the new release's manifest/checksums. Version-only generation is checked locally; platform CI must validate its own final artifact consumers. The historical [React verification](react-verification.md) and [SwiftUI verification](../../platforms/swiftui/VERIFICATION.md) retain their original 0.4.0 scope rather than being relabelled as new evidence.

This pass does not establish manual TalkBack/VoiceOver/NVDA, physical minimum-OS devices, full platform text scaling, maximum Dynamic Type, exhaustive RTL/Tab behavior, real Safari or Flutter Windows/Linux runtime acceptance. Android popup position unit cases include RTL/window edges and tall content; screenshots do not establish every narrow-screen or large-text case. A macOS Flutter CUA capture was black despite a passing integration test, so visual observations use its web build. A user-withdrawn web dialog-position investigation is excluded; the Android popup overlap was independently observed in the installed native sample and fixed.
