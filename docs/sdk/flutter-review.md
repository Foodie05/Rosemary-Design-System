# Flutter shared-contract review

Read-only review of SDK 0.4.0 on 2026-10-13, before the Flutter owner finishes the six-platform matrix. Initial findings are retained below alongside the focused runtime evidence subsequently reviewed. This records source observations and targeted checks still required. It does not claim that all findings are fixed or that Flutter acceptance is complete. The owner reported a clean library analyze, seven baseline widget regressions and a separately unpacked source consumer/gallery test; those tests do not by themselves cover the cases below.

Secondary checks: Tabs currently navigates from controlled value rather than the actually focused option, so repeated arrows after a refused selection may not advance focus. Its measurement occurs on build; verify parent-only layout resizing and changed child font widths without remounting. Loading uses correct shared cycle duration and stops/reset-to-static on reduction/lifecycle; the generated 300 ms appearance threshold currently has no direct public delay entrance, so document the host visibility boundary or provide one. These are source observations pending the owner's focused response.

Positive source evidence: complete opaque sRGB colors validate with actual role-pair diagnostics; local theme inheritance and system/ancestor/application reduced motion combine with OR; overlay capture preserves theme, direction, media/text scaling and localization; controllers, focus nodes and overlay entries have disposal paths; date/time are public local values rather than timezone-bearing timestamps. These observations do not replace actual screen-reader, device, keyboard, six-platform build or runtime validation.

Focused evidence reviewed: `platforms/flutter/rosemary_ui/test/review_regressions_test.dart` and owner-executed `/Volumes/MacData/Rosemary/build/flutter-review-tests.log`, five widget scenarios, all passed. The high-contrast scenario supplies an explicit complete palette via `MediaQuery.highContrast` at 200% text; all color diagnostics pass and no overflow exception occurs. This is framework simulation, not an OS high-contrast screen-reader/device result. The log was read independently, but the review agent did not execute those five cases. The source archive's equivalent targeted cases and final-main CI are still required for release evidence.

Follow-up source concerns sent to the owner after reviewing those tests: Upload currently checks `mounted` after its chooser future but does not recheck `enabled`; Retry/Cancel lack a filename in their accessible action labels; a direct ISO commit while the date panel is already closed can leave a rejected draft in the input because `changeOpen(false)` returns early. These are not covered by the passing initial-disabled and accepted-direct-commit scenarios. End/RTL time navigation, controlled refusal and overlay trigger restoration remain targeted checks rather than inferred successes.
