# Rosemary Forma 1.3.0

状态：正式规范修订；对应 SDK 0.5.0 发布候选。尚未发布的 SDK 产物不能表述为可下载正式版本。SDK 发布状态由精确提交的验收和 Release 记录决定。

## 共享来源

`design/tokens.json`（schemaVersion 2）是 45 个语义角色、排版、尺寸和动效的共享契约，`design/contracts.json` 保留 33 个基础组件 ID。`design/color-recipe.js` 是门户和 Web SDK 共用的纯函数配方；Material Color Utilities 0.4.0 提供 HCT、色域映射与量化，Rosemary 定义角色分配与面积约束。`design/color-system.json` 记录规则，生成结果不得手改。

四种 SDK 均提供完整明暗主题、局部继承、严格颜色验证和实际对比诊断。原生通过完整配方 JSON 交换颜色，不用各平台近似算法重新解释种子色；系统壁纸取色是宿主能力，不是跨平台一致性的替代。Web 的 `generateColorRecipe` / `createColorScheme` 可用于 Node、SSR 和浏览器，计算不读取 DOM、网络、存储或系统外观。

## 颜色与层级

- 页面使用 `canvas`，内容组使用 `surface-group`，内嵌区使用 `surface-inset`，浮层使用 `surface-floating`。导航与顶栏使用各自表面及 `on-*` 内容色；导航应比顶栏、正文更沉。
- 当前导航使用 `navigation-active` / `on-navigation-active`。选中块与导航底色至少 3:1，文字至少 4.5:1。不得使用侧边高对比竖条或弧条代替当前项。
- HCT 目标彩度上限：页面和内容表面 6、导航 10、顶栏 8、柔和/辅助容器 16、反馈容器 12。sRGB 离散映射的小幅误差由自动验收限额约束。HEX 与图片候选共用配方；鲜亮模式增强小面积操作与重点，不能把源图片色直接铺到大区域。
- 成功、警告、危险、信息保留稳定语义色相，搭配文字或图形说明。`sun` / `sky` 保留兼容名称，含义分别为点缀和辅助容器，不承诺固定色相。
- 所有默认配方必须通过角色对比检查。消费者自定义颜色不静默纠正；返回诊断，由宿主成对调整。对比诊断不代表人工读屏或完整可访问性验收。

45 个角色的完整名称、默认值和各平台 camelCase 映射以共享 JSON 和生成类型为准；旧 24 色主题不得被误认作完整 1.3 主题。

## 容器、控件与焦点

同级部件先用网格、留白和排版组织；内容组与内嵌区用轻微色差；浮层增加柔和阴影和必要的轻边缘。分隔线保留给表格比较、拖拽、真实分界等任务，不给每个部件默认套框。

文本输入采用 `field-fill` / `field-hover`，移除常驻底线与底部聚焦条。SDK 0.5.0 候选组件以紧贴轮廓、向内绘制的 1.5px 主题色细线表示聚焦：仅在上、下边以点击横坐标的投影为起点，沿轮廓向两侧展开，转过圆角后覆盖左右边，约 220ms 完成；失焦时整体在 90ms 内淡出。圆角继承实际输入容器，不增加外围间隙。键盘或程序聚焦从上下边中点展开；减少动态时立即显示和隐藏，强制颜色模式使用系统高亮。组合搜索框以整体填充区域为边界。错误提示保留错误色与文本。选择触发器采用填充、完整标签和清晰下拉图标，不依赖整圈默认描边。按钮和链接仍须有清晰键盘焦点；高对比/强制颜色模式可以恢复系统完整边界。搜索输入与搜索容器形成一个连续区域，不叠加多层框线。

## 按钮的光学平衡

同组按钮共用尺寸档、文字基线、字重和内边距；主要样式不得用额外宽度或高度强调。文字、次要与实心按钮的视觉重量有意不同，不要求所有操作同样突出。加载必须保留原标签和布局。

暗色主题的主要、危险实心底向内收 1 个逻辑单位（`button.darkFillInset`），用于减轻亮色底的外扩感。仅修正填色轮廓，布局框、内容中心、键盘焦点和点击区域保持原尺寸；次要和文字按钮不缩。Web 在原有 1px 透明边界内绘制，原生单独内缩背景形状。高对比/强制颜色模式取消这项微调，恢复完整边界。该 1 单位取值是 Rosemary 的光学选择，不是其他规范规定的数值，也不能据此宣称每种自定义颜色都获得相同的主观观感。

参考依据：[Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) 用同尺寸与样式建立成组关系；[Fluent 2 Button](https://fluent2.microsoft.design/components/web/react/core/button/usage) 保留主要操作的突出程度，并降低次要动作的视觉重量。

复选框的状态标记只由一个绘制层负责；原生输入保留语义与键盘行为，不能叠加旧伪元素、浏览器标记和新图形。选中、未选中、混合、禁用以及高对比状态均应检查。

## 形状与曲率

统一视觉体验不等于所有部件使用相同半径。共享基础为控件 8、内容容器 12、大面板／对话框 20 个逻辑单位；胶囊和功能性圆形保留自身形状。20px 方形复选框使用基础控件曲率的一半（4），避免小控件看起来像圆形单选；这是比例派生值。按部件的体量、层级与边缘关系选用角色，同类部件在不同页面共用角色，不再零散指定 5、7、9、14、16 等独立值。

同一工具栏中并排、等高的语言选择和外观切换共用外层曲率（12），不能因一个是字段、另一个是分段容器就分别套用 8 和 12。它们共享 `--preference-radius`；外观选中底按共同外框减去 2 的内缩得到 10。主导航、子品牌导航和典型案例不得各自覆盖这组几何。

紧贴嵌套且共用轮廓中心的部件，内层圆角由外层减去实际内缩量推导：12 的分段容器搭配 4 的内边距时，选中底为 8；内缩 2 时为 10。这些是几何派生值，不新增一套无关尺度。相距较远的独立控件仍按自身角色选取，不把所有嵌套内容都强制减到零。

贴屏的抽屉只在游离边缘使用大面板曲率，贴边保持直角；浮动侧栏取消外围描边，以表面色和阴影表达边界。内部可操作元素保留可见键盘焦点。品牌资产、抽象插画、功能性圆形及缩略布局图形的几何不按控件半径机械替换。

门户通过 `tokens.json.radiusPx` 生成 CSS 别名，SDK 通过同一 `design/tokens.json.radius` 生成平台类型，均由构建验证保持同步。

## 网格、图标与滚动

Web 内容最大宽度 1480px，同一页面的面包屑、标题、内容及页脚共用响应式外边距。常规列距 24，紧凑列距 16；桌面品牌区与顶栏共用 76 高度与中心线。原生使用逻辑单位和可用宽度适配，不能把 Web 像素值强制套用到所有窗口；字体缩放、RTL 和安全区优先保留。中文标题按完整短语换行，不能靠裁剪掩盖溢出。

功能图标共用 24 单位画布、1.6 描边、圆端连接；顶栏主图标推荐显示为 20，辅助下拉提示可以更小。原生不得默默替换为 SF Symbols 或 Material 图标。

侧栏与正文的滚动状态独立，边界手势不能串到正文；模态导航锁定背景并在关闭后恢复。门户隐藏外层两条滚动条视觉，表格/代码/下拉保留必要提示。原生应用遵循宿主平台的滚动条与辅助技术策略，不以隐藏滚动条作为达标条件。

## 动效与系统偏好

状态 180ms，输入反馈 120ms；进入、退出、布局等使用共享 motion token。进入与退出可中断和反转，以真实完成回调收尾，不用固定定时器猜测结束。系统或宿主任一要求减少动态时，停止非必要循环和位移并保留状态信息。前后台切换、卸载及快速反复操作必须释放监听和动画资源。

## 跨平台触感交互

`design/interaction-motion.json` 与纯计算的 `motion-physics.js` 定义按压、释放和位移的质量、刚度与阻尼；由生成器同步为四种 SDK 的交互参数。SDK 0.5.0 候选将这些参数用于默认控件；实际运行与系统覆盖仍按每端证据验收。

按钮按下时轻微压缩，松开后由当前位移和速度继续运行阻尼弹簧，而不是反复播放固定弹跳片段。常规按钮按压目标为 0.974；小型选择标记按比例压缩。快速连点沿当前状态反向，拖出或取消时平稳回位，不能额外触发操作；失焦、页面隐藏、卸载时取消残留动画。

下拉选项固定在触发器边缘，按展开方向逐步揭露，关闭沿原路径收回。空间不足才向上展开。ARIA 状态立即更新，关闭中的选项不可交互；鼠标、触摸、键盘与辅助技术保持原有语义。选中定位和锚点测量使用布局框，不读取临时按压缩放后的错误位置。

减少动态时不创建缩放与展开动画，切换状态、焦点、错误和结果照常生效。共享参数不代表各系统渲染结果逐帧相同；物理弹簧使用平台原生求解器，减少动态、高对比和受控语义优先。人工读屏与最低系统的验收不能由动画参数或编译通过推断。

## 发布验收

四种 SDK 真实消费相同 45 色和新表面规则，主题切换、嵌套继承、浮层继承、键盘和减少动态必须保留。每端单独记录构建、实际运行与未测范围。0.5.0 最终产物只能来自同一最终 main SHA 的完整 CI，不用此前 0.4.2 或中途提交替代；未通过该门槛前不创建正式 tag、不发布 registry。


## 搜索、导航与辅助偏好

就地展开式搜索用于当前集合、高频筛选和内容库，结果仍在当前内容区。宽度足够且搜索为主要任务时可以默认展开；窄屏提供明确入口。Esc 先清空查询，再收起空搜索并返回入口。弹窗检索用于跨章节或低频的全站查找，保留导航空间；Esc 关闭并保留查询，焦点回到入口。响应式变化不能悄悄改变搜索范围。本门户使用全站搜索弹窗，组件预览同时展示两种样式。

顶栏保持固定高度与位置，不随正文切换或抽屉／弹窗开关淡出。只锁定根滚动，不因切换 body 的 overflow 重新建立 sticky 容器；导航抽屉和搜索弹窗避开顶栏所在高度。

明暗偏好在所有屏幕使用单个、至少 44×44px 的图标按钮。图标与可访问名称指明切换目标，默认可以跟随系统，手动切换后保存明暗选择。语言选择不作为导航必填项：只有两种及以上真实可用语言且有切换需求时才显示；低频入口可以放在设置或页脚。单语言门户和案例不放占位语言下拉，多语言选项使用语言本身的名称并保留当前位置。

相邻章节使用带轻底色和方向箭头的链接入口，保持可见点击线索。相邻章节上方不再画分隔线，页脚只保留一条结构分界。多行输入不提示常识性的 Enter 换行，只说明确有必要的字数限制或特殊提交快捷键。


选择器的触发器是展开容器的固定头部，不能独立缩放回弹造成接缝。展开时头部与选项区共用填充色、连续外轮廓，靠近接缝的圆角与箭头按同一展开曲线变化，阴影只出现在外侧。关闭时反向收回；选项滚动仅改变自己的视口，不带动页面或顶栏。


按钮实际宽度变化统一采用约 180ms 的快速非线性收敛：内容或状态改变时从当前可见宽度接续到新宽度，快速再次变化不得排队播放旧尺寸。布局尺寸动画与按压缩放独立。滑块的程序设值立即同步原生值、表单和无障碍语义，绘制层在 180ms 内平滑跟随；指针拖动时直接跟手。滑动选中标记沿已有共享弹簧曲线移动，不用线性位移。减少动态时直接到目标状态。


## 字段要求、反馈与验证位置

要求、逐条校验结果、错误说明及继续操作所需的验证部件必须紧邻对应文本框，优先置于下方；正文式要求使用 14px 可读字号与稳定行距。验证码或 CAPTCHA 是某个字段继续操作的前置条件时，就在该字段下方显示；加载、失败、重试和恢复也留在同一组；待验证使用中性状态，失败才标记错误，成功提示留在验证区域。不得把这些内容移到页面顶部、表单末尾或另一个无关弹窗。不要等提交后才告诉用户格式要求。

初始与空值状态均为中性，要求始终可见。字段聚焦后的首次非空脱焦才开始校验：逐条满足显示对勾，不满足显示红叉及危险色，并将该字段的 1.5px 贴合轮廓改为危险色。此后编辑实时更新，输入法组合阶段延迟到 compositionend。清空立即移除全部对错、aria-invalid 和红色描边；重新输入再次等待首次脱焦。使用图形与文字状态，不仅靠颜色；要求关联 aria-describedby，规则状态改变时适度播报。

统一密码创建策略来自 `design/input-validation.json`：

- 8–32 个字符。
- 仅允许 U+0021–U+007E 的可打印 ASCII：英文字母、数字、英文标点。空格、非英文字符、emoji、控制字符不允许。
- 字母、数字、英文标点三类至少包含两类；大写与小写都属于“英文字母”一类。
- 不做 trim、Unicode 规范化或截断。注册、设置与重置采用同一策略；登录只作非空检查，既有凭据由身份服务验证。

昵称的长度与字符要求来自具体产品，不擅自附加密码的字符限制。门户示例采用 1–32 个字符且不能全为空白，用于演示相同的字段状态机制。客户端体验规范不替代服务端对原始输入的校验。
