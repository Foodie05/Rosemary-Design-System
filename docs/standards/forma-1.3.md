# Rosemary Forma 1.3.0

状态：正式规范修订；对应 SDK 0.5.0 发布候选。尚未发布的 SDK 产物不能表述为可下载正式版本。SDK 发布状态由精确提交的验收和 Release 记录决定。

## 共享来源

`design/tokens.json`（schemaVersion 2）是 45 个语义角色、排版、尺寸和动效的共享契约，`design/contracts.json` 保留 33 个基础组件 ID。`design/color-recipe.js` 是门户和 Web SDK 共用的纯函数配方；Material Color Utilities 0.4.0 提供 HCT、色域映射与量化，Rosemary 定义角色分配与面积约束。`design/color-system.json` 记录规则，生成结果不得手改。

四种 SDK 均提供完整明暗主题、局部继承、严格颜色验证和实际对比诊断。原生通过完整配方 JSON 交换颜色，不用各平台近似算法重新解释种子色；系统壁纸取色是宿主能力，不是跨平台一致性的替代。Web 的 `generateColorRecipe` / `createColorScheme` 可用于 Node、SSR 和浏览器，计算不读取 DOM、网络、存储或系统外观。

## 颜色与层级

- 页面使用 `canvas`，内容组使用 `surface-group`，内嵌区使用 `surface-inset`，浮层使用 `surface-floating`。导航与顶栏使用各自表面及 `on-*` 内容色；导航应比顶栏、正文更沉。
- 当前导航使用 `navigation-active` / `on-navigation-active`。选中块与导航底色至少 3:1，文字至少 4.5:1。不得使用侧边高对比竖条或弧条代替当前项。
- HCT 目标彩度上限：页面和内容表面 6、导航 10、顶栏 8、柔和/辅助容器 16、反馈容器 12。sRGB 离散映射的小幅误差由自动验收限额约束。HEX 与图片候选共用配方；鲜亮模式增强小面积操作与重点，不能把源图片色直接铺到大区域。
- 成功、警告、危险、信息保留稳定语义色相，搭配文字或图形说明。`sun` / `sky` 保留兼容名称，含义分别为点缀和辅助容器，不承诺固定色相。
- 所有默认配方必须通过角色对比检查。消费者自定义颜色不静默纠正；返回诊断，由宿主成对调整。对比诊断不代表人工读屏或完整可访问性验收。

45 个角色的完整名称、默认值和各平台 camelCase 映射以共享 JSON 和生成类型为准；旧 24 色主题不得被误认作完整 1.3 主题。

## 容器、控件与焦点

同级部件先用网格、留白和排版组织；内容组与内嵌区用轻微色差；浮层增加柔和阴影和必要的轻边缘。分隔线保留给表格比较、拖拽、真实分界等任务，不给每个部件默认套框。

文本输入采用 `field-fill` / `field-hover`，一条 `field-line` 底线，聚焦时使用整合在底部的 2px 提示。错误提示保留错误色与文本。选择触发器采用填充、完整标签和清晰下拉图标，不依赖整圈默认描边。按钮和链接仍须有清晰键盘焦点；高对比/强制颜色模式可以恢复系统完整边界。搜索输入与搜索容器形成一个连续区域，不叠加多层框线。

## 按钮的光学平衡

同组按钮共用尺寸档、文字基线、字重和内边距；主要样式不得用额外宽度或高度强调。文字、次要与实心按钮的视觉重量有意不同，不要求所有操作同样突出。加载必须保留原标签和布局。

暗色主题的主要、危险实心底向内收 1 个逻辑单位（`button.darkFillInset`），用于减轻亮色底的外扩感。仅修正填色轮廓，布局框、内容中心、键盘焦点和点击区域保持原尺寸；次要和文字按钮不缩。Web 在原有 1px 透明边界内绘制，原生单独内缩背景形状。高对比/强制颜色模式取消这项微调，恢复完整边界。该 1 单位取值是 Rosemary 的光学选择，不是其他规范规定的数值，也不能据此宣称每种自定义颜色都获得相同的主观观感。

参考依据：[Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) 用同尺寸与样式建立成组关系；[Fluent 2 Button](https://fluent2.microsoft.design/components/web/react/core/button/usage) 保留主要操作的突出程度，并降低次要动作的视觉重量。

复选框的状态标记只由一个绘制层负责；原生输入保留语义与键盘行为，不能叠加旧伪元素、浏览器标记和新图形。选中、未选中、混合、禁用以及高对比状态均应检查。

## 网格、图标与滚动

Web 内容最大宽度 1480px，同一页面的面包屑、标题、内容及页脚共用响应式外边距。常规列距 24，紧凑列距 16；桌面品牌区与顶栏共用 76 高度与中心线。原生使用逻辑单位和可用宽度适配，不能把 Web 像素值强制套用到所有窗口；字体缩放、RTL 和安全区优先保留。中文标题按完整短语换行，不能靠裁剪掩盖溢出。

功能图标共用 24 单位画布、1.6 描边、圆端连接；顶栏主图标推荐显示为 20，辅助下拉提示可以更小。原生不得默默替换为 SF Symbols 或 Material 图标。

侧栏与正文的滚动状态独立，边界手势不能串到正文；模态导航锁定背景并在关闭后恢复。门户隐藏外层两条滚动条视觉，表格/代码/下拉保留必要提示。原生应用遵循宿主平台的滚动条与辅助技术策略，不以隐藏滚动条作为达标条件。

## 动效与系统偏好

状态 180ms，输入反馈 120ms；进入、退出、布局等使用共享 motion token。进入与退出可中断和反转，以真实完成回调收尾，不用固定定时器猜测结束。系统或宿主任一要求减少动态时，停止非必要循环和位移并保留状态信息。前后台切换、卸载及快速反复操作必须释放监听和动画资源。

## 发布验收

四种 SDK 真实消费相同 45 色和新表面规则，主题切换、嵌套继承、浮层继承、键盘和减少动态必须保留。每端单独记录构建、实际运行与未测范围。0.5.0 最终产物只能来自同一最终 main SHA 的完整 CI，不用此前 0.4.2 或中途提交替代；未通过该门槛前不创建正式 tag、不发布 registry。
